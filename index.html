LED ghosting patch for Whitestar pinball machinesLED-Ghosting-Patch für Whitestar-Flipper

With LEDs in the lamp matrix, a lamp can glow faintly when the lamp one row further in the same column is lit. On The Simpsons Pinball Party (TSPP) this is lamp n−8, for example Shoot Again (lamp 3) glowing while lamp 11 is on. This page changes the lamp driver of your own CPU ROM so that the ghost is gone. Everything runs in your browser; the file is not uploaded.

This is a compatibility adjustment of the lamp-matrix timing for LED lamps on hardware that was designed for incandescent bulbs. Independent tool, not affiliated with, endorsed by or connected to Stern Pinball, Sega or any rights holder. No ROM data is included, stored or distributed.

    What the patch changesWas der Patch ändert

    The lamps are a matrix: one row is switched on at a time, together with the column lines of the lamps that should light in that row. Every step of the lamp interrupt the original program does this:

    1. switch the row off and clear the column lines,
    2. compute the next row,
    3. put the new column data out, then switch the new row on.

    The patch changes two things in this sequence and nothing else:

    1. The old column data stays on until the new data replaces it, instead of being cleared together with the row. The row that was just switched off can finish turning off through its own lamps, which were lit anyway.
    2. Rows without any lit lamp are no longer switched on. The only exception is row 1: it gets a pulse of 2.5 µs, because the watchdog of the I/O board listens on that output. In our circuit calculation the pulse is far too short to make the row conduct.

    The new output step (29 bytes) goes into unused space at the end of the ROM; the old step jumps there. The checksum is re-balanced so that the game's own ROM self-test still passes. In total 48 bytes differ from the original.

    What stays the same

    • The row is switched off at the same moment as before. The lamp interrupt runs a few microseconds longer; in the emulator the game, lamp shows and switch scanning keep their speed (no growing delay).
    • The version text (e.g. "CPU 5.00") is not changed. The game compares it with the copy in its battery memory at power-up; a change would reset all settings, audits and high scores. With this patch nothing is reset.
    • Only the checksum shown in the test menu is different (TSPP 5.00: $D9FF instead of $5BF0). That is how you recognise your adjusted chip.

    Die Lampen bilden eine Matrix: Immer ist eine Zeile eingeschaltet, dazu die Spaltenleitungen der Lampen, die in dieser Zeile leuchten sollen. Bei jedem Schritt des Lampen-Interrupts macht das Originalprogramm:

    1. Zeile aus und Spaltenleitungen löschen,
    2. nächste Zeile berechnen,
    3. neue Spaltendaten ausgeben, dann die neue Zeile einschalten.

    Der Patch ändert an diesem Ablauf zwei Dinge und sonst nichts:

    1. Die alten Spaltendaten bleiben stehen, bis die neuen sie ersetzen, statt mit der Zeile gelöscht zu werden. Die gerade abgeschaltete Zeile kann so über ihre eigenen Lampen, die ohnehin leuchteten, fertig abschalten.
    2. Zeilen ohne leuchtende Lampe werden nicht mehr eingeschaltet. Einzige Ausnahme ist Zeile 1: Sie bekommt einen Impuls von 2,5 µs, weil der Watchdog des I/O-Boards an diesem Ausgang hängt. Nach unserer Schaltungsrechnung ist der Impuls viel zu kurz, um die Zeile leiten zu lassen.

    Der neue Ausgabeschritt (29 Bytes) liegt in ungenutztem Platz am Ende der ROM; der alte Schritt springt dorthin. Die Prüfsumme wird so ausgeglichen, dass der ROM-Selbsttest des Spiels weiter besteht. Insgesamt unterscheiden sich 48 Bytes vom Original.

    Was gleich bleibt

    • Die Zeile geht im selben Moment aus wie vorher. Der Lampen-Interrupt dauert einige Mikrosekunden länger; im Emulator behalten Spiel, Lampenshows und Schalterabfrage ihr Tempo (kein wachsender Versatz).
    • Der Versionstext (z. B. „CPU 5.00“) wird nicht geändert. Das Spiel vergleicht ihn beim Einschalten mit der Kopie im batteriegepufferten Speicher; eine Änderung würde alle Einstellungen, Audits und Highscores zurücksetzen. Mit diesem Patch wird nichts zurückgesetzt.
    • Nur die im Testmenü angezeigte Prüfsumme ist anders (TSPP 5.00: $D9FF statt $5BF0). Daran erkennst du deinen geänderten Chip.

    Why the ghost appears

    According to our circuit model: the row transistors are switched through a high-value resistor, so they turn off slowly. When the row goes off while its column lines are cleared, nothing pulls the row wire up, and the transistor stays half on. As soon as the column data for the next row arrive, current flows through the lamp in the old row of that column: the ghost. A filament bulb needs far more current to glow, so it never showed; an LED glows at microamps.

    With the patch the old row finishes turning off through its own lamps while their column data are still out. Rows without lamps are never switched on, so they have nothing to turn off.

    Warum der Geist entsteht

    Nach unserem Schaltungsmodell: Die Zeilentransistoren werden über einen hochohmigen Widerstand geschaltet und gehen deshalb langsam aus. Wird die Zeile abgeschaltet, während ihre Spaltenleitungen gelöscht sind, zieht nichts die Zeilenleitung hoch, und der Transistor bleibt halb an. Sobald die Spaltendaten der nächsten Zeile kommen, fließt Strom durch die Lampe der alten Zeile in dieser Spalte: der Geist. Eine Glühbirne braucht viel mehr Strom zum Leuchten, deshalb fiel das früher nicht auf; eine LED leuchtet schon bei Mikroampere.

    Mit dem Patch schaltet die alte Zeile über ihre eigenen Lampen fertig ab, solange deren Spaltendaten noch anliegen. Zeilen ohne Lampen werden gar nicht erst eingeschaltet und müssen daher auch nicht abschalten.

    InstallingEinbau

    1. Read your CPU EPROM (or use the file from your PinMAME set) and keep it; keep the original chip.
    2. Patch it here and check that the page shows a green result.
    3. Optional: run the patched file in PinMAME.
    4. Burn it to a new EPROM of the same type and fit it. Test menu → checksum should show the value from the table.
    5. To undo: put the original chip back. Nothing in the battery memory changes.
    1. CPU-EPROM auslesen (oder die Datei aus deinem PinMAME-Satz nehmen) und aufbewahren; den Original-Chip behalten.
    2. Hier patchen und prüfen, dass die Seite ein grünes Ergebnis zeigt.
    3. Optional: die geänderte Datei in PinMAME starten.
    4. Auf ein neues EPROM gleichen Typs brennen und einsetzen. Testmenü → Prüfsumme sollte den Wert aus der Tabelle zeigen.
    5. Rückbau: Original-Chip wieder einsetzen. Im batteriegepufferten Speicher ändert sich nichts.
